## Design Context

### Users

Hydrographic survey planners, sonar data processors, reviewers, and auditors use this application at an operations desk after a survey run. They need to compare planned transects with imported tracks, judge navigation quality, inspect explainable coverage gaps, and record a human decision without implying control of a vessel or sonar.

### Brand Personality

Precise, composed, and accountable. The interface should feel like a professional chart-room instrument: dense enough for repeated technical work, calm under scrutiny, and explicit about evidence and safety boundaries.

### Aesthetic Direction

Use a light, chart-plotter-inspired workspace with crisp geometry, restrained ink neutrals, hydrographic teal, safety yellow, and coral only for meaningful severity. Geometry is the visual asset: survey boundaries, transects, swaths, gaps, scale ticks, and coordinate annotations should carry the identity. Avoid marketing composition, decorative nautical motifs, oversized cards, glass effects, gradients, rounded pills everywhere, and generic dashboard metric grids.

### Design Principles

1. Keep the map or geometry evidence central; controls support inspection rather than compete with it.
2. Show provenance beside decisions: coordinate system, checksum, algorithm version, request ID, and state should remain scannable.
3. Use color redundantly with labels and shapes so navigation quality, run state, and gap severity never depend on hue alone.
4. Prefer compact tables, split workspaces, drawers, and inline state controls over modal-heavy workflows.
5. Adapt mobile views into a readable vertical inspection flow without hiding core actions or evidence.
